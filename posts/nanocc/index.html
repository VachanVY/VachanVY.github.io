Extending nanocc: Implementing extern and static from Scratch (draft)

2026/02/01

What is nanocc? What’s this post about?

nanocc is a minimal implementation of a C compiler in C and C++23. You can find its source code here. In this post I will be implementing the extern and static keywords to nanocc, explaining the steps I take along the way. Also, I’ll be explaining the codebase of nanocc as I go along, so that you can understand how it works.

Lexer

  • The code for the lexer is in lib/Lexer and include/nanocc/Lexer directories.
  • The lexer is implemeted in pure C without any dependencies (in lib/Lexer/CAPI), with a C++ interface (lib/Lexer/Lexer.cpp) so other parts of the compiler can use it.

Extending Lexer for extern and static

  • Okay, so I need to add extern and static keywords to the lexer.

  • In lib/Lexer/CAPI/tokens.def, I will add the following lines:

    ...
X(EXTERN, "extern")
X(STATIC, "static")
...

  • This is used by

    // lib/Lexer/CAPI/lexer.h
typedef enum {
#define X(name, str) name,
#include "tokens.def"
} CTokenType;

    and

    // include/nanocc/Lexer/Lexer.hpp
enum class TokenType {
#define X(name, str) name,
#include "../../../lib/Lexer/CAPI/tokens.def"
#undef X
};

    to get create enum of tokens for both C and C++ interfaces.

  • Now I need to add regex patterns for these tokens in lib/Lexer/CAPI/lexer.c.

  • Now define the extern_fsm and static_fsm in lib/Lexer/CAPI/regex.h and implement them in lib/Lexer/CAPI/regex.c.

    // lib/Lexer/CAPI/regex.c

/// @brief `std::regex("extern\\b")` | "\\b" is important since it shouldn't match "external" or something like that
/// @param s
/// @return 6 if matches else 0
int extern_fsm(const char* s) {
    if (s[0] != 'e' || s[1] != 'x' || s[2] != 't' || s[3] != 'e' || s[4] != 'r' || s[5] != 'n' ||
        !_iswordbreaker(s[6])) {
        return 0;
    }
    // we only care about `extern` part, not about the wordbreaker now that we know it matches correctly
    return 6; // length of "extern"
}

/// @brief `std::regex("static\\b")` | "\\b" is important since it shouldn't match "statics" or something like that
/// @param s
/// @return 6 if matches else 0
int static_fsm(const char* s) {
    if (s[0] != 's' || s[1] != 't' || s[2] != 'a' || s[3] != 't' || s[4] != 'i' || s[5] != 'c' ||
        !_iswordbreaker(s[6])) {
        return 0;
    }
    // we only care about `static` part, not about the wordbreaker now that we know it matches correctly
    return 6; // length of "static"
}

Parser

  • Parser takes the tokens from the lexer and creates an Abstract Syntax Tree (AST) from them.
  • Abstract Syntax Tree: A Tree representation of the syntactic structure of the source code. Abstract here means that not every detail from the source code is represented in the tree, only the essential parts.
  • The Parser also checks for syntax errors and reports them.
